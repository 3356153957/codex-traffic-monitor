# 实现说明

这里记录 Codex Traffic Monitor 在采集、历史读取和资源占用方面的实现取舍，面向想了解内部行为或参与开发的读者。用户向的说明见 [README](../README.md)。

## 采集与资源占用

收起到托盘后暂停表格排版刷新，并释放界面的历史副本和列表，采集、每秒保存新增流量及代理识别仍继续；恢复窗口时立即读取最新统计，并恢复筛选、选中与滚动位置。无流量时摘要每 30 秒写一次心跳，停止、异常和丢事件变化立即保存。去向说明按实际显示需要生成，历史数据没有变化时复用统计、去向列表与图表，搜索和排序复用已加载的数据。输入搜索时只更新去向列表、数量和详情，不重建其他图表和表格。

历史明细按块扫描换行，完整行直接解析，跨块行才拼接；实际包含相同记录日期的时间范围，在同一轮刷新中共用去向汇总和排序结果。各范围的统计口径保持独立，新流量和跨日仍会更新。

实时快照先复制账本与状态，再在采集锁外排序、补充代理、DNS 与地区线索；CSV 导出也先取得独立快照再写文件，减少界面查询和导出对事件入账的等待。快照里的字节、进程及会话计数对应同一次采样。

历史内部的相同目标由日期与统计范围共享，追加修改时再复制，不减少保留的记录或 CSV 去向。连接账本只保留显示所需的前三个域名及混合策略状态，每次完整注释仍写入会话明细。地区数据库采用文件映射，减少整库私有副本。程序使用适度的内存节省回收策略，可能增加回收次数；不限制历史数量，常驻内存仍会随历史规模和窗口状态变化。

采集中的进程启停由 ETW 实时跟踪，全量进程扫描每 5 秒兜底；没有目标进程时不读取全系统 TCP 表。DNS 线索通过 Windows 缓存接口在进程内读取，不再周期启动 PowerShell。代理控制器发现缓存 5 秒并复用客户端，连接快照仍每 500 毫秒读取。

明细写入复用单行 UTF-8 缓冲，减少大量连接同时入账时的临时内存，每批仍刷新到磁盘。代理采样优先使用当前配置里最近可用的控制器，减少失效候选反复超时；配置变化或控制器失效时重新选择。

单文件 EXE 自带运行时，采用无需运行时解压程序集的打包方式，以降低常驻内存；安装包和便携 ZIP 仍压缩下载。原生 DLL 不打进单文件（`IncludeNativeLibrariesForSelfExtract=false`），随 EXE 放在安装目录：自解压会写到 `%TEMP%\.net`，同用户的普通进程可以抢先放入同名 DLL，再由提权后的监控程序加载。

开机任务以 `HighestAvailable` 运行，登录时不经 UAC。`InstallLocationSecurity` 只在 EXE、同目录 DLL、`amd64` 及各级父目录都没有非管理员可写、可删改子项或可改权限的条目，且所有者是 SYSTEM、Administrators 或 TrustedInstaller 时，才允许注册该任务；`--location-check` 可输出当前副本的判断。
